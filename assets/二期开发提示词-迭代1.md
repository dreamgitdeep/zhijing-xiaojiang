## 2. 数据层（教师端与学生端共用）

在 `supabase/schema.sql` 基础上新增三张表（本轮只用到 `cases / tasks / student_runs / stage_records`）：

```sql
create table if not exists public.cases (
  id text primary key, title text not null, summary text,
  background text, facts jsonb, refs jsonb,
  site_data jsonb, cover_url text, created_at timestamptz default now()
);

create table if not exists public.tasks (
  id text primary key, case_id text references public.cases(id),
  name text not null, requirements jsonb, reference_solution jsonb,
  rubrics jsonb, stages jsonb, stage_weights jsonb,
  pass_score int default 60, hours numeric, difficulty text,
  cover_url text, status text default 'draft',
  created_by uuid references public.profiles(id), created_at timestamptz default now()
);

create table if not exists public.student_runs (
  id bigserial primary key,
  task_id text references public.tasks(id), user_id uuid references public.profiles(id),
  current_stage text default 'S1', status text default 'in_progress',
  best_score int default 0, total_score int default 0,
  started_at timestamptz default now(), finished_at timestamptz
);

create table if not exists public.stage_records (
  id bigserial primary key,
  run_id bigint references public.student_runs(id) on delete cascade,
  stage_key text not null, version int default 1,
  payload jsonb,        -- 该阶段学生产出：对话记录、表单答案
  ai_review jsonb,      -- 评阅结果
  score int, created_at timestamptz default now()
);
```

RLS：`cases / tasks` 所有登录用户可读、仅教师可写；`student_runs / stage_records` 本人读写、教师只读。
**`tasks` 表对学生的查询必须走视图 `tasks_student_view`（剔除 `reference_solution` 列）**，不得直接 select * 后在前端过滤。

`local` 模式（`NEXT_PUBLIC_DATA_MODE=local`）：任务配置直接读 `chuangzhi-task.json`，学生进度写 localStorage（key：`zjxj.design.runs.v1`）。

## 4. 页面与交互规格

### 4.1 案例卡片列表 `/design`
卡片：封面图（用 `site-map-full.svg` 或后续封面图）/ 任务名称 / 案例摘要（`case.summary`）/ 学时与难度 / **进度徽章**（未开始 · 进行中 阶段 x/6 · 已完成 x 分）/ 一句话要求（`requirements[0]`）。
右上角显示"我的案例 1 个"。点击整卡进入背景页。

### 4.2 案例背景页
- 主区为 `case.background` 正文，**保留引用标注 `[1][5-6]`**，页面底部列出 `case.refs` 来源
- 右侧（桌面）或下方（移动）信息卡：逐条展示 `case.facts`（地点/面积/原状/建成/用地性质/运维模式/重要身份）
- 右下角固定主按钮 **「进入探索」**（未登录时先跳登录，登录后回到本页）

### 4.3 转场动画（关键交互）
点击「进入探索」后：
1. 背景卡使用 **FLIP 技术**从全屏（宽 100%、高约 100vh）过渡到顶部横条（高 **56px**），时长 **420ms**，缓动 `cubic-bezier(0.4, 0, 0.2, 1)`；正文缩放并淡出（`opacity 0 → 1` 于横条内容）
2. 横条内容：`site-map-full.svg` 缩略图（54×34）+ `summary` 单行文本 + **「展开全文」** 按钮
3. 「展开全文」点击后以抽屉从顶部展开（高度 60vh），内含完整背景与 facts，可再次收起
4. **必须支持 `prefers-reduced-motion: reduce`**：尊重系统设置时改为直接显示横条、不做动画
5. 横条固定不随滚动消失（`sticky top: 0`）

### 4.4 工作台三区布局（S1 / S2 通用）
| 位置 | 内容 |
|---|---|
| 顶部条 | 案例背景横条（含展开抽屉）+ 左侧「案例列表」返回 + 阶段进度 `阶段 1/6` + 阶段名 |
| 中部主区 | **AI 对话区**（占 60% 宽） |
| 右侧栏 | 上方：本阶段表单卡；下方：**AI 评阅卡** |
| 移动端 | 右侧栏折叠为底部抽屉，先看对话，点「填写表单」升起 |

阶段条：横向 6 个圆点 + 名称，S1/S2 可点，S3–S6 灰态显示「未解锁」。

### 4.5 阶段 1 · AI 对话区
- 消息气泡：学生右侧（主色气泡）、AI 左侧（浅底气泡），流式输出（打字机效果）
- 首次进入注入一条 AI 开场白：
  > 我是本次任务的场地顾问。关于创智农园这块地，你可以向我提问——**我只回答你问到的信息**，没问到的不会主动告诉你。建议先从场地的基本条件问起。
- 输入框占位符：`问点什么？例如：这块地的光照怎么样？`；Enter 发送 / Shift+Enter 换行；含「停止生成」
- 头部计数器：`已提问 7 / 20`、`关键项 4 / 9`（**只显示数量，不列出缺哪些**）
- 底部快捷问题 chips（3 条，仅作示例引导）：「这块地的土壤情况怎么样？」「排水好不好？」「周边都是些什么人用？」
- 达到 20 次上限后输入框禁用，提示"提问次数已用完，请提交诊断结论"
- 右下角主按钮 **「完成调研，填写诊断表」**：点击后在中部主区切换到 **8 项诊断表**（`diagnosisForm`），每项一个文本域 + `hint` 提示；填写后「提交并进入定位」

### 4.6 阶段 2 · 定位与原则（右侧栏上方卡片）
- 主定位：从 `positioningOptions` 4 项中单选 1 个**主定位** + 最多勾选 2 个次定位
- 设计原则：从 `principleOptions` 10 项中多选（7 正确 + 3 干扰，**干扰项与正确项视觉上不做任何区分**）
- 理由输入框：`请说明你的定位与所选原则与本地块条件的对应关系（150–400 字）`，实时字数统计
- 「确定」提交 → 触发评阅（右侧下方卡片进入 loading：`AI 正在评阅你的调研记录与设计定位…`）

### 4.7 AI 评阅卡（统一结构，S1/S2 共用）
```
得分 83 / 100 · 达标            （通关线取 task.passScore，默认 60）
维度条：提问覆盖 18/25 · 提问深度 20/25 · 结论正确 27/30 · 逻辑连贯 18/20
优点：2–3 条（每条引用学生原话或具体答案）
不足：2–3 条（每条末尾标注规则编号，如「[coverage] 未询问地下管线」）
改进建议：1–2 条（可执行，指向下一阶段动作）
按钮：[ 按建议修改并重交 ]  [ 进入下一阶段 ]（未达标时该按钮置灰）
```
- 重交规则：**无限次重交，取最高分**；每次评阅写入 `stage_records`（`version` 自增），卡片显示 `本次 83 · 历史最佳 88`
- 进入下一阶段的条件：得分 ≥ `passScore`；S1 通过后解锁 S2，S2 通过后显示"完成后四个阶段（待开发）"

## 5. AI 接口规格

### 5.1 `POST /api/design/chat`（对话 AI）
**请求**：`{ taskId, runId?, messages: [{role, content}] }`
**上下文装配（严格按此顺序，缺一不可）**
1. 系统提示词（逐字使用）：
```
你是《植物造景》课程的场地顾问，正在带一名高职学生完成社区花园的场地调研。
规则（必须严格遵守）：
1. 只依据下方【场地资料】回答；资料中没有的内容，回答"课程资料中未涉及该信息"，绝不推测或编造。
2. 只回答学生问到的内容，绝不主动补充其他场地信息。
3. 学生若问"这里该种什么/怎么设计"，回答"这需要你自己根据已获得的信息判断，我不能替你做设计决策"。
4. 若学生问的是成因或可行性（如"为什么排水差""土壤能不能改良"），可以就资料中已有信息作解释。
5. 每次回答不超过 3 句、120 字，只陈述事实，不给出建议。
```
2. 【任务要求】：`task.requirements`
3. 【案例背景】：`task.case.background`（仅背景文字，不含 facts 明细）
4. 【场地资料】：**只注入命中的 1–2 条问询库条目**（见匹配算法），格式 `条目主题：answer`
5. **禁止注入**：`referenceSolution`、`rubrics`、未命中的问询条目、其他学生的记录

**匹配算法（服务端，不调用大模型）**
- 取学生最新一条提问，与 `inquiry.entries` 逐条做 `keywords` 包含匹配（命中关键词数降序 → `importance=critical` 优先 → 取前 2 条）
- 命中 0 条时：返回固定话术"课程资料中未涉及该信息。你可以换个角度问，例如场地条件、周边人群或使用限制。"
- 记录 `hitEntryIds` 用于过程评分（覆盖度、深度）

**返回**：SSE 流式文本 + 末尾附 `meta: { hitEntryIds: [], askedCount, criticalHitCount }`

### 5.2 `POST /api/design/review`（评阅 AI）
**请求**：`{ taskId, runId, stageKey, payload }`（`payload` 为该阶段学生产出：对话记录 / 表单答案）
**上下文**：系统提示词（逐字）：
```
你是《植物造景》课程的过程性评价教师。请根据【评分标准】对学生的【阶段答卷】逐项打分。
要求：
1. 每个维度给 0–权重 的分数，并给出 1 句理由。
2. 每个扣分点必须引用学生的原话或具体答案，并标注触发的维度 key。
3. 不得提供任何设计方案、不得替学生给出正确答案要点。
4. 只输出 JSON，不要任何多余文字。
输出结构：{"score":整数,"total":100,"pass":布尔,"dimensions":[{"key","label","score","max","reason"}],
"strengths":[字符串],"issues":[{"text","ruleKey"}],"suggestions":[字符串]}
```
再依次注入：【评分标准】（`task.rubrics` 或该阶段 `stages[].rubrics`）、【场地事实】（`chuangzhi-nongyuan.json` 的 constraints + inquiry 全量，**仅供评阅判断，不得出现在输出中**）、【参考设计答案】（`task.referenceSolution`，**仅服务端**）、【阶段答卷】。
**兜底**：未配置模型 Key 时，用规则计算返回（覆盖度=命中 critical 条目数/9×满分、其余维度给基线分），并在 `issues` 中注明"（离线模式：依据规则估分）"。
